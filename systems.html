Precast Engineering ERP

One inquiry record from the client's BOQ to a production-ready SAP product

Every order needed its own take-off, drawings, memos and submittals in separate files, and SAP products were created one screen at a time, so the price, the drawing and the SAP product could drift apart.

How it works

A ribbon button opens a job; the job reads the inquiry record and live SAP data; nothing is written to SAP until the preview is approved; every write is read back and logged.

What I built

  • Inquiry-centred platform: BOQ import, item analysis, cost take-off from live SAP BOMs, quotation create and revise, new FG/BOM/routing/QM creation, with the design, drawing and submittal engines linked into the same record.
  • Every tool follows one contract: a ribbon button, a JSON job, then preview, apply, verify and log. SAP writes stay locked until each operation is approved.
  • Version 1 runs daily; version 2 rebuilds it on a tested Python core with 4,252 automated tests.

One inquiry record carries

  • BOQ import and item analysis
  • Cost take-off from live SAP BOMs
  • Quotation create and revise
  • New SAP products: FG, BOM, routing and QM
  • Cages, routings and production versions created in SAP
  • Design memos, drawings and material submittals linked to the same record

SAP S/4HANA Cloud: master data to Go-Live

A manufacturing product model built from an empty system

JDCO moved onto SAP S/4HANA Cloud (Public Edition) with no prior system data. Engineering, production, planning, sales and finance needed one product model they could all trust from day one.

How it works

Engineering defines each product once: material code, BOM, and routing on work centers linked to cost centers. Costing, procurement, production and planning all read that same model.

What I built

  • Material coding standard, BOM and routing logic, work centers linked to cost centers, and classification/AVC for configurable box culverts.
  • Excel/VBA and Python generators that produce FG, BOM, routing and inspection data from reference products, loaded through Migration Cockpit and OData.
  • Engineering connected to costing, procurement, production and planning through one product model.
  • Training for the technical office and users across departments, then first-line support after Go-Live.

Analytics and planning on S/4HANA

Dashboards and planning tools from live SAP data

Management needed production, dispatch and material-planning views straight from SAP, without manual exports.

How it works

An OData extraction mirrors SAP into a local database; the scheduled reports and the Power BI model read the mirror instead of manual exports.

What I built

  • A 35-entity OData extraction and local data mirror (~9M rows) with a data dictionary and join map.
  • 29 scheduled HTML and Excel reports, and a code-generated Power BI production model.
  • A raw-material plan that checks the production plan against SAP stock and open purchase orders.

AI-augmented engineering workflow

Engineering-led development with independent review and automated verification

Building an ERP, design engines and a BIM system next to a full technical-office workload needs leverage without losing control of quality.

How it works

Every change is planned by the lead engineer, built by an AI coding agent, reviewed by a model from a different family and released only through automated test gates.

What I built

  • A multi-agent workflow across Claude Code and OpenAI Codex: work is routed by model, reviewed by a different model family, and released only through automated test gates.
  • Safety guards and a single configuration for models, effort and delegation; every decision logged.
